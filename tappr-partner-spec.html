Acces & Activare Partner

Cum se deblochează modul partner și ce câmpuri noi intră în play

ℹ
Modul Partner se activează manual din Admin Panel după ce clientul a plătit cei 500€. Un admin bifează is_partner = true pe userul respectiv. Toată UI-ul de partner este gated pe acest flag.
⚠
Affiliate-ul existent în DB (affiliates) este separat de sistemul de partner. Partenerul are propriul tabel partner_profiles și logica sa de comision 50%. Nu suprapune cu sistemul affiliate vechi.
👤
Must have
Flag pe users table
Adaugă coloana is_partner și partner_activated_at la tabelul users.
  • is_partner — boolean, default false
  • partner_activated_at — timestamptz, null dacă nu e activ
  • Admin îl poate seta din panoul de administrare existent
  • Middleware verifică flagul și redirecționează spre /partner dacă e true
🔐
Must have
Gating Route Middleware
Protejează toate rutele /partner/* — accesibile doar dacă is_partner = true.
  • Adaugă matcher în middleware.ts pentru /partner/*
  • Dacă user nu e partner → redirect la /dashboard
  • Dacă user nu e autentificat → redirect la /login
  • Nu expune nimic din UI partner la users normali
🔗
Must have
Generare Link Referral Unic
Fiecare partner primește automat un link referral unic la activare. Linkul este generat o singură dată și stocat în partner_profiles.
  • Format: tappr.me/ref/[cod-unic-8-caractere]
  • Codul se generează automat la crearea profilului de partner (nanoid sau UUID partial)
  • Linkul de referral redirecționează spre landing page-ul de signup cu ?ref=[cod] în URL
  • La signup cu ?ref=[cod], se creează automat o înregistrare în partner_referrals și se asociază noul user cu partenerul
  • Dacă codul din URL nu există → signup normal, fără referral

-- RLS Policies pentru partner_profiles
CREATE POLICY "partner sees own profile"
ON partner_profiles FOR SELECT
USING (user_id = auth.uid());

CREATE POLICY "partner sees own referrals"
ON partner_referrals FOR SELECT
USING (partner_id IN (
SELECT id FROM partner_profiles
WHERE user_id = auth.uid()
));

-- Adaugă partner_referral_clicks în Supabase Realtime publication
ALTER PUBLICATION supabase_realtime ADD TABLE partner_referral_clicks;

API Routes Noi

Toate endpoint-urile care trebuie create în src/app/api/partner/

Method Route Descriere Prioritate
GET /api/partner/profile Returnează profilul complet al partenerului: earnings, referral code, payout method Must
GET /api/partner/earnings Earnings pe luni (ultimitele 12), total all-time, pending payout Must
GET /api/partner/referrals Lista completă a referral-urilor cu plan, status, valoare lunară, dată conversie Must
GET /api/partner/stats Click-uri pe linkul de referral, rata de conversie, device breakdown, geo breakdown Should
GET /api/partner/leaderboard Top 10 parteneri după earnings (anonimi: arată locul tău + locurile vecine) Should
POST /api/partner/payout-request Partenerul solicită un payout; creează entry în partner_payouts cu status=requested Must
PATCH /api/partner/payout-method Salvează metoda de plată (IBAN sau PayPal email) în partner_profiles.payout_method Must
POST /api/partner/suggestions Trimite o sugestie nouă pentru roadmap Nice
GET /api/partner/suggestions Lista tuturor sugestiilor (toate partenerele văd toate sugestiile) Nice
GET /ref/[code] Route publică — înregistrează click, redirect spre landing page cu ?ref=[code] Must
POST /api/admin/partner/activate Admin endpoint — activează partner mode pentru un user, generează referral code Must
PATCH /api/admin/partner/payout Admin marchează un payout ca plătit, actualizează pending_payout și total_earned Must
// Exemplu: /ref/[code]/route.ts — click tracker + redirect
export async function GET(req, { params }) {
const { code } = params;
const supabase = createClient();

// 1. Verifică că referral code-ul există
const { data: partner } = await supabase
.from('partner_profiles')
.select('id')
.eq('referral_code', code)
.single();

// 2. Loghează click-ul (fire and forget)
if (partner) {
supabase.from('partner_referral_clicks').insert({
partner_id: partner.id,
country: getCountry(req),
device: getDevice(req),
});
}

// 3. Redirect spre signup cu codul în URL
return NextResponse.redirect(
`https://tappr.me/signup?ref=${code}`
);
}

Paginile Partner — Detalii UI

Ce conțin exact fiecare pagină, ce componente, ce date afișează

🏠
Must have — Prima pagina văzută
/partner — Overview Dashboard
Prima pagină văzută la login. Trebuie să arate earnings-ul în 3 secunde.
  • 4 metric cards mari: Câștigat luna aceasta | Total all-time | Referrals active | Rata de conversie
  • Grafic earnings — bar chart pe ultimele 6 luni (similar cu "Recent Clicks" din dashboard-ul normal)
  • Activitate recentă — ultimele 5 evenimente: "Nou referral: Plan 250€", "Câștig creditat: 125€"
  • Quick-copy link — linkul de referral cu buton copy vizibil, nu îl ascunde
  • Banner payout — dacă pending_payout > 50€, afișează banner "Ai X€ disponibili pentru retragere"
👥
Must have
/partner/referrals
Lista clienților aduși, cu detalii despre fiecare.
  • Tabel cu: nume/email referral, plan (100/250/500€), data join, status (activ/churned)
  • Coloana "Comision lunar" — cât aduce fiecare pe lună partenerului
  • Badge colorat pentru plan (verde=500, portocaliu=250, albastru=100)
  • Filtrare după status (activi / toți / churned)
  • Total MRR generat vizibil sus
💰
Must have
/partner/earnings
Centrul financiar al partenerului.
  • Grafic line chart — earnings pe zi în luna curentă
  • Tabel istoric plăți: dată, sumă, status (paid/pending/requested)
  • Secțiune "Solicită Payout" — câmp sumă + buton, cu validare minimul 50€
  • Secțiune metodă de plată — IBAN sau PayPal (formular simplu save)
  • Breakdown: câștiguri per referral activ în luna curentă
🔗
Must have
/partner/link
Totul despre linkul de referral.
  • Linkul mare, cu buton copy și buton share
  • QR code al linkului (librăria qrcode.react există deja în proiect)
  • Stats: total click-uri, click-uri azi, click-uri săptămâna aceasta
  • Grafic click-uri pe ultimele 14 zile
  • Breakdown device (mobile/desktop) și top 5 țări
📊
Should have
/partner/stats
Funnel complet de conversie.
  • Funnel vizual: Click-uri → Signups → Plătitori
  • Rata de conversie click→plată ca număr mare vizibil
  • Geo heatmap — din ce țări vin click-urile
  • Device split donut chart
  • Comparație luna aceasta vs luna trecută
🏆
Should have
/partner/leaderboard
Ranking parteneri — motivator principal.
  • Top 10 parteneri după earnings luna aceasta
  • Partenerul logat vede locul lui evidențiat (chiar dacă e pe 15)
  • Afișat anonim: "Partener #1 — 2,400€" (nu numele real)
  • Badge special pentru locul 1, 2, 3
  • Resetare lunară — arată și all-time ranking separat
📣
Should have
/partner/promo — Kit Promovare
Materiale gata de folosit pentru promovare.
  • Texte pentru social media (Instagram, LinkedIn, WhatsApp) — copy cu un click
  • Bannere descărcabile (1080x1080, story format) cu linkul partenerului inclus
  • Email template de trimis cunoștințelor
  • Script pentru DM-uri
💬
Nice to have
/partner/suggestions
Input de produs de la parteneri.
  • Formular simplu: titlu + descriere sugestie
  • Lista sugestii existente cu statusul (Open / In Progress / Done)
  • Partenerii pot vota sugestiile altora (up-vote)
  • Sugestiile cu Done arată data implementată
06

Notificări Realtime

Ce evenimente triggerează notificări live în interfață (Supabase Realtime)

ℹ
Proiectul folosește deja Supabase Realtime pentru anomaly_alerts. Același pattern — adaugă partner_referral_clicks și partner_referrals în publicație și abonează-te pe client.
🔔
Must have
Nou referral înregistrat
Când cineva se înscrie folosind linkul partenerului.
  • Toast notification în colțul ecranului: "Nou utilizator s-a înregistrat prin linkul tău!"
  • Badge counter pe sidebar la "Referrals" se actualizează live
  • Card de activitate în Overview se actualizează
💚
Must have
Referral a plătit (conversie)
Momentul de dopamină — referral-ul a trecut la plan plătit.
  • Toast special: "🎉 [Referral] a trecut la planul 250€! Câștigați 125€/lună"
  • Earnings counter în header se actualizează live
  • Pending payout se mărește automat
💸
Should have
Payout aprobat de admin
Adminul a marcat plata ca efectuată.
  • Notificare: "Plata de X€ a fost procesată"
  • Tabelul de plăți se actualizează din pending în paid
  • Pending payout scade automat
📉
Nice to have
Referral a churnat
Un client adus a anulat subscripția.
  • Notificare discretă (nu toast agresiv): "Un referral a devenit inactiv"
  • Earnings forecast se actualizează
  • Status în tabelul de referrals → churned

Email Triggers

Emailuri trimise automat via Resend — ce template-uri trebuie create

✉️
Must have
Welcome Partner
Trimis la activarea contului de partner de către admin.
  • Conține: linkul personal de referral
  • Explicație comision 50% și cum funcționează
  • Link direct la /partner dashboard
  • Triggerul: când adminul setează is_partner = true
🎉
Must have
Referral a plătit
Email când un referral trece la plan plătit.
  • Subject: "Ai câștigat X€ — referral-ul tău a plătit!"
  • Arată planul ales și comisionul lunar generat
  • CTA: "Vezi câștigurile tale"
  • Triggerul: insert în partner_referrals cu converted_at setat
📊
Should have
Raport lunar
Email automat la 1 ale lunii cu sumarul lunii trecute.
  • Total câștigat luna trecută
  • Număr referrali noi și activi
  • Pending payout disponibil
  • Piggyback pe cron-ul existent de la 08:00 UTC
💳
Should have
Confirmare Payout
Email când adminul aprobă și procesează o retragere.
  • Suma plătită, metoda folosită
  • Reference number dacă există
  • Mulțumire + CTA să continue promovarea
